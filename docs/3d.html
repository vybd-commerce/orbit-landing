The operating stack

00 — Sources

Your data isn't wrong. It's scattered.

Six to nine systems, each internally consistent, none agreeing on what's in stock, what shipped, or what it cost to get there.

6–9 systems · 2 SKU conventions · reconciliation = 1 person

  • ERP says 400 units. The 3PL says 340. Both are right, on different dates.
  • The mapping table nobody owns is load-bearing for three teams.
  • Your best ops hire spends four hours a week being an integration.

01 — Context layer

One model, built once.

A read-only projection over every system. Entities resolved a single time, so "how much of this do we have" has one answer instead of six.

1 schema · read-only · entities resolved once

  • Two-zone projection. Raw mirror on one side, resolved model on the other. Nothing writes here.
  • Scoped reads. Each task sees a slice, not the warehouse — less compute, fewer wrong answers.
  • No migration. Your systems stay exactly where they are.

02 — Agent layer

Workers, not a chatbot.

Each agent owns one job and runs it on a schedule. The model decides what to look at; deterministic compute decides the answer.

bounded jobs · deterministic math · propose-only

  • One job per agent. Demand signal, deduction matching, markdown candidates — not a general assistant.
  • The math isn't the model. An LLM picking which SKUs to examine is reliable; an LLM doing the arithmetic is not.
  • Agents propose. None of them can execute. That's the next two layers' job.

03 — Application layer

Where your team actually works.

Surfaces built on the same projection. Your ops lead sees a ranked queue of decisions, not a dashboard that asks them to go find the problem.

queue not dashboard · one surface · no new login for the floor

  • Decisions, not charts. A dashboard tells you inventory is off. This tells you which 14 SKUs and what to do.
  • Reasoning attached. Every proposal shows the numbers behind it and which systems they came from.
  • Nothing new to learn for the people who live in the ERP all day.

04 — Governance layer

Rules the agents can't cross.

Not a policy document — enforcement sitting in the path of execution, where an agent without permission simply cannot perform the action.

scoped permissions · value thresholds · full audit

  • Scoped permissions. An agent that can propose a markdown cannot issue a PO.
  • Threshold gate. Above the line routes to review by default. There is no override path.
  • Audit log. Every read, proposal and write attributable after the fact.

05 — Review

Nothing writes back unapproved.

Work arrives decided, not delegated. Your operator sees the proposal, the reasoning and the value at risk, and spends thirty seconds where they used to spend an afternoon.

named sign-off · ranked by value at risk · ~30s per decision

  • Ranked by exposure, not by arrival time.
  • Named approval. Every write traces to a person who approved it.
  • Rejection is signal. The next proposal is narrower for it.

06 — The loop

Approved work goes back where it came from.

The stack reads top-down but closes upward. An approved proposal writes into the same systems it was read from, and the outcome becomes context for the next run.

no migration · no new source of truth · compounding context

  • The systems stay the systems. Nothing to rip out, nothing new to maintain.
  • Month three beats month one because it has seen what you approved.
  • Absorbs complexity, not headcount. Same 39-handoff chain, 13 people instead of 34.
